# QYFM 蓝牙后台播放与通话恢复设计

## 目标

- 通话开始时暂停当前电台，通话结束后恢复。
- 不为锁屏显示台标或媒体信息；保留一个不写媒体元数据的最小 AVSession，以满足系统后台音频播放要求。
- 长期保存最多 3 个蓝牙音频设备，每个设备独立设置连接后是否自动播放。
- “蓝牙自动播放总开关”控制整体自动播放能力；新绑定设备默认不自动播放，必须单独勾选。
- 开启设备自动播放后，不应用续播时间窗口限制。
- 应用在后台存活时，连接匹配设备即启动应用播放界面并播放。
- 应用在手机重启后通过系统自动启动恢复后台监听；用户强行停止应用时，普通应用无法自行复活。

## 方案

1. 创建并激活最小 AVSession，只发布播放/停止状态，不写标题、台标等媒体元数据。保留音频后台长时任务；真机锁屏不显示媒体卡片。
2. 新增最多 3 个蓝牙绑定记录，字段为 `deviceId`、`deviceName`、`autoPlay`、`lastConnectedAt`。达到 3 个后，新设备进入待绑定状态，不自动挤掉已有记录。
3. 用户删除任意旧记录后，待绑定设备立即补入并默认关闭自动播放，可再单独开启。
4. A2DP 连接事件读取设备名称并更新绑定记录；命中 `autoPlay=true` 时忽略续播窗口，直接唤醒或播放。
5. 启动时启动蓝牙监听和音频后台长时任务。系统自动启动默认由系统设置控制，应用提供状态诊断和操作说明。
6. 通话暂停继续依赖系统 AudioInterrupt；AVPlayer 与 FFmpeg AudioRenderer 均采用开始暂停、结束恢复的语义，用户手动暂停时不自动恢复。

## 非目标与限制

- 不申请企业、系统或 root 权限。
- 不承诺用户强行停止应用后仍能被蓝牙拉起。
- 不尝试隐藏 HarmonyOS 对普通应用后台长时任务强制显示的系统文字通知。

## 验证

- 单元测试覆盖三设备上限、显式删除替换、设备级自动播放判断、最小 AVSession 后台策略和通话恢复语义。
- ArkTS/Hvigor 构建通过。
- 真机验证通话式音频中断、后台切换、设置持久化和已连接蓝牙设备记录。
